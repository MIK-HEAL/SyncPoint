# SyncPoint v0.1 Release Notes

## What is SyncPoint?

SyncPoint is a local coordination protocol for editor AI agents. It prevents unsafe continuation — when agents resume from stale state, edit files they don't own, or skip required approvals.

## Highlights

### Synchronization Truncation
When an agent tries to continue and the path is unsafe, SyncPoint **blocks** and explains why. This is the core value: cutting off bad continuation before it becomes a merge conflict.

### Five Protocol Primitives
- **FileClaim** — declare file ownership; overlapping claims create blockers automatically
- **SyncGate** — hard stop until resolved (not just acknowledged)
- **SyncTransaction** — checkpoint that requires approval before another agent resumes from it
- **PatchProposal** — diff checked for ownership, format, and constraint violations before apply
- **Wake** — sync obligation telling the next agent what action is needed

### CLI v0.1 Commands

| Command | Description |
|---|---|
| `syncpoint init` | Initialize `.syncpoint/` state |
| `syncpoint demo` | Run the disaster blocking demo |
| `syncpoint status` | Show who is blocked, why, and what to do |
| `syncpoint claim <paths>` | Declare file ownership |
| `syncpoint checkpoint` | Save progress + context capsule |
| `syncpoint resume` | Resume from latest capsule/checkpoint |
| `syncpoint wake` | Check or acknowledge pending sync obligations |

### Explainable Output
Every blocker shows:
- **Who** is blocked
- **Why** (file conflict, missing approval, constraint violation)
- **What** needs to happen (suggested CLI commands)

### Demo
`syncpoint demo` creates an isolated workspace and walks through:
1. Agent A claims a file exclusively
2. Agent A checkpoints — creates a sync transaction
3. Agent B tries to claim the same file — **BLOCKED**
4. Approval + gate resolution — both agents unblocked

### Editor Integration
- MCP server for Cursor, VS Code, and other MCP-compatible editors
- VS Code extension with Sync View (sessions, blockers, patches, wakes)

## Architecture

```
syncpoint-core    — protocol types, state machines, constraint evaluator
syncpoint-server  — application services, SQLite, tRPC, SSE
syncpoint-cli     — operator CLI (this package)
syncpoint-mcp     — MCP adapter for editor AI agents
syncpoint-sdk     — typed client for integrations
vscode-extension  — Sync View
```

## Requirements
- Node.js >= 20
- pnpm >= 9

## Install

```bash
npm install -g @syncpoint/cli
```

Or for local development:

```bash
pnpm install && pnpm build
syncpoint demo
```

## Publishing

The npm release is three packages published in dependency order:

```bash
syncpoint-core
syncpoint-server
@syncpoint/cli
```

Prepare and verify local release tarballs:

```bash
pnpm release:npm
```

This builds, typechecks, tests, packs all three packages, installs the packed tarballs into a temporary project, and runs `syncpoint init`, `syncpoint demo`, and `syncpoint status`.

Publish dry-run:

```bash
pnpm publish:npm
```

Publish for real after npm login:

```bash
npm login
pnpm publish:npm -- --yes
```
